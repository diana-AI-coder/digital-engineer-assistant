# ADR-002: свой mdrack вместо готовой векторной БД

**Статус:** принято, 2026-10

## Контекст

Для RAG нужны: нарезка .md на осмысленные куски, полнотекстовый + векторный поиск, выдача цитат агенту. Кандидаты: LlamaIndex, Chroma, Qdrant, готовые MCP-серверы для Obsidian.

## Решение

Свой инструмент **mdrack**: SQLite (FTS5 + векторный индекс) + чанкинг markdown по заголовкам + MCP-сервер и CLI.

## Почему не готовые

- Готовые решения чанкуют текст «в лоб»; markdown требует структурного парсинга: заголовки → секции, секции → чанки с сохранением таблиц и код-блоков.
- SQLite — один файл, ноль дополнительных сервисов, переносимо вместе с vault.
- Полный контроль над поиском (гибрид RRF, точечный поиск идентификаторов, см. ADR-003).

## Последствия

- (+) своё — подстраивается под задачу;
- (+) минимальные зависимости: stdlib sqlite3, эмбеддинги по HTTP;
- (−) свой код надо поддерживать и тестировать.
