# ADR-003: номера ГОСТ — regex-экстрактором, не токенизатором

**Статус:** принято, 2026-10

## Контекст

Типичный запрос инженера: «что требует ГОСТ 22.13330?». Номера ГОСТ имеют вид `22.13330.2011` — с точками. Стандартная токенизация (по пробелам/пунктуации) разрезает номер на части, и BM25/векторный поиск не находит точного совпадения. LLM при этом подменяет номер похожим из памяти (путает 22.13330 и 21.1101 — реальный случай из проекта).

## Решение

Двухслойная схема:

1. **Regex-экстрактор** — вытаскивает из запроса номера вида `\d{2}\.\d{5}(\.\d{4})?` и ищет точечно (FTS-запросом по точному номеру или отдельным полем).
2. **BM25/гибрид** — вторым слоем, когда точного номера нет или нужен контекст.

## Последствия

- (+) номера ГОСТ находятся надёжно, независимо от токенизации;
- (+) меньше шансов, что LLM «перепишет» номер в ответе;
- (−) покрывает только формат номеров, а не произвольные идентификаторы.
