# ADR-003: точечные идентификаторы — regex-экстрактором, не токенизатором

**Статус:** принято, 2026-10

## Контекст

Инженерные и не только запросы часто содержат точные идентификаторы с точками внутри: номера стандартов (ГОСТ 22.13330.2011), патентов, коды нормативов, версии спецификаций. Стандартная токенизация (по пробелам и пунктуации) разрезает такой идентификатор на части, и BM25/векторный поиск не находит точного совпадения. LLM при этом подменяет номер похожим из памяти (в пилотном кейсе ассистент путал ГОСТ 22.13330 и 21.1101).

## Решение

Двухслойная схема:

1. **Regex-экстрактор** — вытаскивает из запроса идентификаторы (например, номера стандартов вида `\d{2}\.\d{5}(\.\d{4})?`) и ищет их точечно (FTS-запросом по точному значению или отдельным полем).
2. **BM25/гибрид** — вторым слоем, когда точного совпадения нет или нужен контекст.

## Последствия

- (+) идентификаторы с точками находятся надёжно, независимо от токенизации;
- (+) меньше шансов, что LLM «перепишет» номер в ответе;
- (−) покрывает только известные форматы идентификаторов, а не произвольные строки.
